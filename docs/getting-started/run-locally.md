# Run Locally

Any Linux, macOS, or Windows (WSL2) machine with **Python 3.10–3.12**, **git**, and
**4 GB of RAM** is enough.

## 1. Get the course

```bash
git clone https://github.com/kwmaeng91/studying-llm-systems-without-gpus
cd studying-llm-systems-without-gpus
```

## 2. Create an environment

```bash
python3 -m venv .venv
source .venv/bin/activate          # Windows (WSL): same command
pip install -r requirements-lab.txt jupyterlab
```

## 3. Launch Jupyter

```bash
jupyter lab docs/lectures/
```

Open any `.ipynb` and run the first cell. `vl.setup()` clones Vidur-Agent into
`~/vidur-agent` the first time. Set `VIDUR_HOME=/some/path` before starting
Jupyter to put it somewhere else.

## Where things are stored

| Path | Contents | Safe to delete? |
|---|---|---|
| `~/vidur-agent/` | Vidur-Agent source and profiling data (~700 MB) | yes, re-cloned on next `setup()` |
| `~/.vidur-lab/predictor_cache/` | fitted runtime predictors (~70 MB per model/GPU/TP) | yes, refit on demand |
| `~/.vidur-lab/runs/` | raw simulator output of every run | yes |
| `~/.vidur-lab/traces/` | workload CSVs generated by `make_trace` | yes |

Override `~/.vidur-lab` with the `VIDUR_LAB_DIR` environment variable.

## Troubleshooting

`RuntimeError: Vidur simulation failed`
: The simulator's log is printed above the error. The most common cause is an
  unprofiled combination (for example Llama-3-8B with TP2 on A100). Check `vl.catalog()`.

The first simulation of a new model or GPU is slow
: Vidur fits its runtime predictors once per (model, GPU, TP) and caches them.
  Later runs take a few seconds.

Out of memory
: The labs keep the simulator's prediction grid small (see `LITE_GRID` in
  `vidur_lab.py`). If you raise those limits, expect memory use to grow
  quickly. The upstream defaults need more than 10 GB.
